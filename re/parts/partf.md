# partf (web/parts/partf.js)
Main script: wait pos>0x5820, `call 0x164dc` (init+loop+cleanup in ONE function, 0x20d), clear VRAM, wait pos>0x6100. Also needs the sprite precalc `0x16945`, run in the original's global init (main 0xe6) -> done in JS `init()` (0.5 s).
* Resources: 49 env map (256x256 indexed, used as the `fs` map of shading mode 3), 50 small sphere object (158 v, static), 51 morph object (650 v, 3 extra key frames, keys [0,1,2,0], shift 7, 128 steps, weight table 0x15860).
* Lib3D: mode 3, shift 1, dist **0x64** (left by part C at 0xa2f1; the harness snapshot has 0x14 because it skips part C: use `ctx.dist=0x14` to compare), flags 0 (sorted), cam 0. Object drawn with `drawObject` (no camera, raw position). Back buffer is flipped with 0x78948 (clear 0).
* Precalc (0x16945): 64 frames x 16 spheres on a ring (obj angle ax=0x400, ay=bx leftover register: object0 = t-1 (0x38 at t=0), object i = angle of i-1 minus 0x400; y=0x64, x=SIN[e]>>2, z=(SIN[e-0x400]>>2)-0xbe, e=(t&0x1f)<<4 +0x100/object), dist 0x14, shift 3, rendered into the back buffer, rows 77..199 RLE encoded ([skip u16][count u16][bytes remapped via table 0x15a60]...0xffff). Byte-exact vs the snapshot (1 223 242 B, 64/64 frames; test re/parts/partf_tmp/pre.mjs).
* Loop (0x16590, per frame): [pal compute 0x168a3 if flag] vsync, [DAC write if flag], flipClear, blit RLE frame (t>>1)&63, morph step, draw object. Timer callback 0x16646 (1 tick/frame) does everything else:
  ax+=0xa, ay+=c1 (9, +2 per bounce), az+=6, advance anim; t<0x80: palette fade-in (all comps = t, shift 7 of source palette 0x15e60); 0x9f..0x165: y = 0x173180 - (t-0x9e)*0x1d4c (ball falls into view); t>=0x166: bounces at t == c7 (560, then += c3; c3 = 206 -4, -10, -16 .. (cf += 6), 7 bounces, last at t=1502) each starting a 63-tick flash (cb) with colour channels from tables 0x15960/0x159e0 (R=G=tbl159e0+0x2a, B=tbl15960/2+0x30, shift 6) and ax += 0x12/tick; after the last bounce phase 1: z += d4 (d4 += 0xb9/tick) fly toward the camera, once d4>0x23f0 whole-screen flash from table 0x15660[d8++] (all comps, 255 steps) then phase 2 with black palette -> loop ends.
  Palette fade (0x168a3): v<2^cl: src*v>>cl ; else src+((63-src)*(v-2^cl)>>cl) (8-bit signed imul).
* Timing: start at pos>0x5820 (frame 0 = tick 1); `frame()` returns false after tick 1805 (render of tick 1805 done) = ~1805 frames (25.8 s). Palette at start: black (original writes zeros itself); at end: black (all comps 0 written on the last tick), VRAM should be cleared by the script. Dist/flags: see above.
* Verification (ticks 1,2,3,50,100..130,160..167,200,300,400,561..563,580..700 : all identical; ticks >700 = later bounces, fly-by flash and end NOT compared, the full harness run is too slow (~1 tick/s when the ball is large); transcribed from the disassembly): back buffer rows 1..197 + faded palette array + DAC identical to the original (own harness copy re/parts/partf_tmp/h.py with hooks at 0x16607, keyed by tick counter [0x163ae]; cmp.mjs). Rows 0/198/199 of the back buffer hold garbage (sqrt table) and are never shown.
* picture57 (main 0x1b0..0x1e9, exported from credits.js) tested vs harness frames: identical (palette within 8-bit rounding), fade-in 65 frames, fade-out 65 frames, harness frame k == JS frame k-1.
